# V0.14.06 — SofIA, emissão revisada e PDF oficial

## Escopo fechado
- Documento para exatamente um Lead ou Cliente; emissão, idempotência e revisão transacionais.
- Coleta persistente entre turnos e revisão vinculada ao payload e aos bytes/modelo cadastrado.
- Consulta de chamados com cliente, endereço vinculado e equipe opcional; IDs opacos para consulta de ficha.
- Portal lista documentos de ambos os destinatários e usa o emissor canônico.
- PDF oficial gerado/download pelo HubRRD, Chromium não-root com sandbox.
- Purga de Lead TESTE bloqueada por documento oficial; documento nunca é descartável.
- Entrega WhatsApp desativada: autorizado recebe 503 `DOCUMENT_TRANSPORT_NOT_CONFIGURED`, sem alterar documento ou criar ACK. Não incluir migration 0023 nem ativar a bridge candidata.
- Sem alteração no HVD ou na bridge instalada. Reconhecimento conversacional por número e escolha da ferramenta no canal não são provados por estes testes de Hub.

## Fonte e organização
Base de integração: `c4915e8` (V0.14.05). Candidato composto em worktree próprio, sem arquivos debug/fixtures temporários. Alterações residuais de transporte existentes no worktree anterior são preservadas fora deste release e não devem ser publicadas por engano.

Os testes DB só podem usar PostgreSQL descartável local com nomes admitidos pelos guards. Configurar `DATABASE_URL` e `POSTGRES_RRD_URL` para o MESMO banco teste, sem imprimir valores. `RRD_ISSUER_DISPOSABLE_DB=1` habilita os testes de emissão; os runners legados exigem `127.0.0.1:55432/rrd_issuer_test`.

```sh
node src/lib/__tests__/portal-draft-issue.integration.mjs
```

PDF e testes de UI devem executar no runtime Chromium sandboxado conforme `docker-compose.yaml`, com fixtures/ambiente descartável. Não usar `--no-sandbox` para obter verde. Não chamar `npm start` com banco de produção durante testes: startup reconcilia e aplica migrations.

## Migração e rollback
Migration nova: `0022_official_documents_lead_recipient.sql`. O journal termina em 0022. A atualização relaxa vínculos opcionais e acrescenta Lead XOR Cliente e revisão imutável; não apaga nem reescreve linhas antigas.

Prova pré-publicação: clone PG17 restaurado de backup privado; hashes/timestamps das 22 entradas históricas coincidem com SQL canônico. Reconcile + migrador oficial executados duas vezes, terminando com 23 entradas. Conteúdo das 32 tabelas comparado pelos campos originais: igual antes/depois.

Antes de produção, preservar backup DB privado e configuração criptografada Coolify. Rollback de aplicação usa a imagem e configuração V0.14.05 preservadas. Não remover colunas/constraints ou restaurar o banco inteiro automaticamente: após novas emissões Lead, código antigo pode não ler esses documentos. Se houver falha após escrita real, manter os dados e aplicar recuperação compatível; restauração de DB exige avaliar as escritas posteriores ao backup.
